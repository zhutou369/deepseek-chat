## 在千帆平台部署 DeepSeek 模型

千帆平台提供了两种主要方式来使用 DeepSeek 模型：直接调用平台预置的 DeepSeek API 服务，或通过自定义模型集成 DeepSeek 的外部 API。考虑到性能测试的便捷性，我们通常会选择千帆平台预置的 DeepSeek 服务。

### 部署步骤概览

1.  **登录千帆平台控制台**：
    在百度智能云控制台导航栏中找到“人工智能” -> “千帆大模型平台”。

2.  **进入“模型工厂”或“模型服务”**：
    在左侧导航栏中选择“模型服务” -> “在线服务”。

3.  **创建推理服务**：
    点击“创建服务”按钮，开始配置您的 DeepSeek 推理服务。

    ![千帆平台创建服务引导](/static/posts/covers/generic.svg)

4.  **选择 DeepSeek 模型**：
    在模型选择界面，搜索并选择 DeepSeek 提供的模型，例如 `deepseek-v2` 或 `deepseek-coder`。请根据您的应用场景选择合适的模型。

5.  **配置服务参数**：
    *   **服务名称**：为您的服务命名，例如 `DeepSeek-V2-Test`。
    *   **资源配置**：这是影响性能的关键。千帆平台通常提供多种规格的计算资源（如 CPU、GPU 数量、内存大小），以及并发数、QPS 限制等。
        *   **标准版/高性能版**：选择不同的服务版本会影响资源分配。
        *   **并发数与 QPS**：根据预期负载设置，初始测试时可以先设置为较低值。
        *   **弹性伸缩**：建议开启，以应对流量高峰。
    *   **服务计费**：了解不同配置下的计费方式。
    *   **模型参数**：设置推理参数，如 `temperature`（控制随机性）、`max_tokens`（最大输出长度）等。这些参数也会影响推理时延。

6.  **确认并发布服务**：
    检查所有配置无误后，点击“确认发布”。服务部署需要一定时间，请耐心等待。部署成功后，您将获得一个 API 地址（Endpoint）和访问凭证（Access Key/Secret Key）。

### 单次请求时延测试

首先，我们测试单个请求的基本时延。

```python
import requests
import time
import json

# 千帆平台服务部署后获取的API信息
QIANFAN_API_URL = "YOUR_QIANFAN_ENDPOINT_URL"
# 千帆平台API Key和Secret Key，用于生成access_token
API_KEY = "YOUR_API_KEY"
SECRET_KEY = "YOUR_SECRET_KEY"

def get_access_token(api_key, secret_key):
    """
    获取百度智能云千帆平台的access_token
    """
    url = f"https://aip.baidubce.com/oauth/2.0/token?grant_type=client_credentials&client_id={api_key}&client_secret={secret_key}"
    response = requests.post(url)
    return response.json().get("access_token")

def test_single_request_latency(access_token, prompt, max_tokens=256, temperature=0.7):
    """
    测试单次 DeepSeek API 请求的时延
    """
    headers = {
        'Content-Type': 'application/json',
        'Accept': 'application/json'
    }
    payload = {
        "messages": [
            {"role": "user", "content": prompt}
        ],
        "temperature": temperature,
        "max_tokens": max_tokens,
        # 其他模型参数，如stream, top_p等
    }
    
    start_time = time.time()
    try:
        response = requests.post(
            f"{QIANFAN_API_URL}?access_token={access_token}",
            headers=headers,
            json=payload,
            timeout=120 # 设置超时时间
        )
        response.raise_for_status() # 检查HTTP错误
        end_time = time.time()
        latency = (end_time - start_time) * 1000 # 转换为毫秒
        
        result = response.json()
        print(f"Prompt: {prompt[:50]}...")
        print(f"Latency: {latency:.2f} ms")
        print(f"Output: {result.get('result', '')[:100]}...")
        return latency, result
    except requests.exceptions.RequestException as e:
        print(f"请求发生错误: {e}")
        return None, None

# 获取access_token
access_token = get_access_token(API_KEY, SECRET_KEY)

if access_token:
    print(f"Access Token: {access_token[:10]}...")
    test_prompt = "请用一句精炼的话介绍人工智能的发展历程。"
    test_single_request_latency(access_token, test_prompt, max_tokens=100)
    
    # 尝试不同输出长度
    print("\n--- 测试长输出 ---")
    long_prompt = "请详细描述大语言模型在自然语言处理领域的应用前景，并列举具体示例。"
    test_single_request_latency(access_token, long_prompt, max_tokens=500)
```

### 并发请求时延测试

为了模拟真实世界的负载，我们将进行并发请求测试。这里使用 `concurrent.futures` 模块进行多线程并发。

```python
import concurrent.futures
import numpy as np

def test_concurrent_requests(access_token, prompt, num_requests=5, max_tokens=256, temperature=0.7, workers=5):
    """
    测试并发 DeepSeek API 请求的时延
    """
    latencies = []
    
    def make_request():
        latency, _ = test_single_request_latency(access_token, prompt, max_tokens, temperature)
        if latency is not None:
            latencies.append(latency)
    
    print(f"\n--- 开始并发测试: {num_requests} 请求，{workers} 并发 ---")
    start_total_time = time.time()
    with concurrent.futures.ThreadPoolExecutor(max_workers=workers) as executor:
        futures = [executor.submit(make_request) for _ in range(num_requests)]
        concurrent.futures.wait(futures)
    end_total_time = time.time()
    
    total_time = (end_total_time - start_total_time) * 1000
    
    if latencies:
        print(f"总耗时: {total_time:.2f} ms")
        print(f"完成请求数: {len(latencies)}")
        print(f"平均单次请求时延: {np.mean(latencies):.2f} ms")
        print(f"时延标准差: {np.std(latencies):.2f} ms")
        print(f"时延 P90: {np.percentile(latencies, 90):.2f} ms")
        print(f"时延 P99: {np.percentile(latencies, 99):.2f} ms")
    else:
        print("没有成功完成的请求。")
    return latencies

# 运行并发测试
if access_token:
    concurrent_prompt = "分析一下人工智能对未来社会的影响。"
    # 5个请求，2个并发
    test_concurrent_requests(access_token, concurrent_prompt, num_requests=5, workers=2)
    # 10个请求，5个并发
    test_concurrent_requests(access_token, concurrent_prompt, num_requests=10, workers=5)
    
    # 对比不同模型参数对并发时延的影响 (例如 max_tokens)
    print("\n--- 对比不同 max_tokens 的并发时延 ---")
    test_concurrent_requests(access_token, concurrent_prompt, num_requests=5, workers=2, max_tokens=100)
    test_concurrent_requests(access_token, concurrent_prompt, num_requests=5, workers=2, max_tokens=500)

```

### 影响时延的关键因素分析

在测试过程中，您会发现以下因素对 API 性能和时延有显著影响：

1.  **模型参数 `max_tokens`**：生成更长的文本通常需要更多的计算资源和时间，导致时延增加。
2.  **并发请求数**：当并发数超过服务承载能力时，请求可能排队，导致时延急剧上升或请求失败。
3.  **千帆平台资源配置**：您在部署时选择的计算资源（如 GPU 数量、CPU 核心数、内存）直接决定了服务的处理能力。高性能配置通常带来更低的时延，但也意味着更高的成本。
4.  **网络时延**：客户端到千帆平台服务器之间的网络传输距离和质量也会影响总时延。
5.  **模型版本**：不同版本的 DeepSeek 模型（例如 DeepSeek-V2、DeepSeek Coder）在计算复杂度上可能有所差异，从而影响推理速度。

## 性能数据分析与优化建议

根据测试结果，您可以进行以下分析和优化：

1.  **基线性能评估**：
    首先确定在单次请求和低并发下的基线时延。这是您的服务在理想状态下的性能指标。
2.  **并发瓶颈识别**：
    逐步增加并发数，观察平均时延、P90/P99 时延的变化。当这些指标开始显著恶化时，说明您可能达到了当前服务配置的并发瓶颈。此时应考虑：
    *   **提升千帆平台资源配置**：增加 CPU/GPU 核心数、内存或选择更高规格的服务实例。
    *   **调整服务 QPS 限制**：千帆平台允许您设置服务的 QPS 上限，合理设置可以防止服务过载。
    *   **开启弹性伸缩**：让平台根据流量自动调整资源，有效应对突发流量。
3.  **优化模型参数**：
    *   **限制 `max_tokens`**：如果您的应用不需要非常长的回复，合理限制 `max_tokens` 可以有效降低时延。
    *   **调整 `temperature`**：较低的 `temperature` 通常生成更确定性的结果，有时也可能影响推理速度（虽然影响不如 `max_tokens` 大）。
4.  **客户端优化**：
    *   **异步调用**：在您的应用中使用异步编程（如 Python 的 `asyncio`）可以提升客户端处理并发请求的效率，避免阻塞。
    *   **批处理 (Batching)**：如果您的应用可以累积多个请求并一次性发送给 DeepSeek API（如果 DeepSeek API 支持），这可以提高吞吐量，但可能会增加单个请求的时延。
    *   **缓存**：对于重复性高或不频繁变化的请求，在客户端或中间层设置缓存可以显著降低时延和 API 调用成本。
5.  **监控与告警**：
    利用千帆平台提供的监控功能，实时关注服务的 QPS、时延、错误率等指标，并设置告警规则，及时发现并解决性能问题。
